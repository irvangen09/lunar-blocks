# Security Policy

## Supported versions

Security fixes are made for the latest release of Moon Blocks only. Please update to the latest version before reporting a problem, and check that it still happens.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Older releases | No |

## Reporting a vulnerability

Please do not report a security problem in a public issue, a pull request, or a discussion.

Report it privately through GitHub:

1. Open the [Security tab](https://github.com/irvangen09/moon-blocks/security) of the repository.
2. Choose **Report a vulnerability**, or go directly to the [report form](https://github.com/irvangen09/moon-blocks/security/advisories/new).
3. Describe the problem.

Please include:

- The affected version of Moon Blocks, and your WordPress and PHP versions.
- What the problem is and what an attacker could do with it.
- The steps to reproduce it, or a proof of concept.
- Any fix you suggest.

## What to expect

- You will get a first reply within 7 days.
- If the report is confirmed, a fix is prepared in private and released as soon as it is ready. You will be told when it ships, and you are welcome to review the fix before that.
- The problem is announced in the changelog and in a GitHub security advisory once a fixed version is available, and you are credited unless you prefer not to be.

Please keep the details private until a fixed version has been released.

## Scope

In scope: the code in this repository, such as the plugin's PHP, the blocks, the settings page, and the files in the release zip.

Out of scope: problems in WordPress itself, in themes or other plugins, or in your hosting, and problems that need an administrator to do something that WordPress already lets administrators do. Those should be reported to their own maintainers.
